# 시험 끝! 게임 모음

시험이 끝난 교실에서 친구들과 가볍게 즐기는 **3D 웹 게임 모음**입니다.
설치 없이 브라우저(학교 PC, 크롬북, 스마트폰, 패드)에서 바로 실행되고, 각자 폰으로 **방 코드**를 넣어 같은 방에서 함께 할 수 있습니다.
카드나 타일이 없어도 **🪑 오프라인 테이블 모드**로 폰을 패처럼 쓰며 얼굴 보고 할 수 있습니다.

### 🪑 오프라인 테이블 모드 (패만 공유)

패드나 폰은 있는데 실물 카드가 없을 때 씁니다. 방을 만들 때 **새 방 모드 → 🪑 오프라인 테이블**을 고르세요.

- 앱은 **섞기, 나눠 주기, 내 패 숨겨 보여 주기, 공용 테이블(버린 더미·판·뽑을 더미)** 만 맡습니다. 합법 수 검사, 힌트, 자동 턴, 봇, 승패 판정은 하지 않습니다.
- 할 수 있는 동작: 패에서 골라 테이블에 내기, 더미에서 뽑기, 테이블에서 가져오기·옮기기, 내 카드 공개/숨기기, 다른 사람에게 주기, 남의 카드 골라 뒤집기(심해 보물섬), 맨 위 뒤집기(급식 다섯!), **턴 넘기기**(누구 차례인지 표시만), **되돌리기**(방장 또는 방금 움직인 사람).
- 모든 동작은 화면 아래 기록에 `민수: 분필 7 → 버린 더미`처럼 **모두에게 공개**됩니다. 판정이 없으니 투명하게 보이는 게 핵심이에요.
- 끝나면 방장이 **👑 방장 메뉴 → 게임 끝 · 승자 정하기**(결과가 시트에 기록됨) 또는 **처음부터 다시 섞기**.
- **📺 테이블 화면**: 대기방의 `📺 테이블 화면 링크`를 교실 TV·패드에서 열면 패 없이 공용 판만 크게 보입니다(`…?room=1234&view=table`).
- 흑백 뒤집기 대전은 숨긴 정보가 없어서 오프라인 모드 대신 **한 기기 2인 대전**을 씁니다.

**교실 운영 팁**
- 한 모둠에 폰 1대씩 + TV에 테이블 화면을 띄우면 실물 카드처럼 둘러앉아 할 수 있어요.
- 급식 다섯!은 반응 속도 게임이라 온라인(1~2초 지연)보다 **한 기기 파티 모드**나 **오프라인 테이블 모드 + 실물 종(또는 손바닥)** 을 추천합니다.
- 규칙 다툼은 기록을 보며 해결하고, 잘못 낸 건 되돌리기로.

```

games/<게임>/                 게임별 폴더 (index.html, style.css, js/)

  net.js                      서버 호출 (온라인 / 브라우저 안 서버)
  local-server.js             server/Code.gs를 브라우저에서 그대로 돌림 (봇 연습·한 기기 모드)
  lobby.js                    공용 대기방 (방 모드 고르기, 코드 참여, 봇, 방장, 폴링, 테이블 화면)

  table3d.js                  새 게임용 3D 테이블 (렌더러·카메라·조명·고르기·카드 메시)
  tutorial-core.js            튜토리얼 진행기 (건너뛰기, 직접 해 보기 단계)

  ui-core.css / ui-core.js    OMR 답안지 디자인, 모달·토스트·배너·컨페티
```

## GitHub Pages로 배포하기

1. 저장소 **Settings → Pages**에서 **Branch: `main` / `(root)`**로 설정합니다(이미 설정되어 있음).
2. `main`에 푸시하면 1~2분 뒤 `https://<아이디>.github.io/<저장소이름>/`에 반영됩니다.
3. 새 기능은 `feature/…` 브랜치에서 만들고 테스트한 뒤 `main`에 합치세요. 그래야 만드는 동안 학생들이 쓰는 사이트가 깨지지 않습니다.

## 온라인 대기방 설정 (구글 시트 + 앱스크립트)

GitHub Pages에는 서버가 없어서, 구글 앱스크립트 웹 앱 **하나**를 모든 게임의 공용 서버로 씁니다.
방 만들기·참여·봇·폴링·오프라인 테이블은 공용이고, 게임별 규칙은 서버 모듈이 처리합니다. 역할이나 손패 같은 숨김 정보는 서버에만 있고, 각자에게는 자기 것만 내려갑니다.

### 처음 설정 (한 번만)

1. 구글 드라이브에서 **새 구글 시트**를 만듭니다.
2. **확장 프로그램 → Apps Script**를 열고, 기본 코드를 지운 뒤 [`server/Code.gs`](server/Code.gs) 내용을 전부 붙여 넣고 저장합니다.
   - [script.new](https://script.new)에서 독립 스크립트로 만들었다면, 위쪽 `const SHEET_ID = '';`에 시트 ID(시트 주소의 `/d/`와 `/edit` 사이)를 넣으세요.
3. **배포 → 새 배포 → 웹 앱**을 고르고, 실행 계정 **나**, 액세스 권한 **모든 사용자**로 배포합니다.
4. 권한을 승인합니다. "확인되지 않은 앱"이 나오면 **고급 → (프로젝트)(으)로 이동**을 누르세요. 직접 만든 스크립트라서 나오는 안내입니다.
5. 나온 웹 앱 URL(`…/exec`)을 [`shared/config.js`](shared/config.js)의 `ONLINE_URL`에 넣고 커밋·푸시합니다.

### 서버 코드를 고친 뒤 — 새 버전으로 재배포 (URL 그대로 유지)

**새 배포를 만들면 URL이 바뀌니 하지 마세요.** 대신:

1. `node tools/build-gs.mjs`로 `server/Code.gs`를 다시 만듭니다.
2. 앱스크립트 편집기에서 코드를 통째로 바꿔 붙여 넣고 저장합니다. 독립 스크립트라면 `SHEET_ID`를 다시 채우세요.
3. **배포 → 배포 관리 → ✏️(수정) → 버전: 새 버전 → 배포**를 누릅니다.
4. 권한 범위가 바뀌었다면 승인 창이 한 번 더 뜰 수 있습니다.

시트의 **`방 기록`** 탭에는 방 생성, 게임 시작, 결과가 한 줄씩 남습니다(시간, 방 코드, 게임, 닉네임, 내용).

**알아두면 좋은 점**
- 방 상태는 앱스크립트 캐시에 6시간 보관됩니다.
- 온라인 모드에서 45초 넘게 연결이 끊긴 사람이나 게임 중에 나간 사람은 봇이 대신 둡니다(오프라인 테이블 모드는 대신 두지 않음).
- 무료 앱스크립트는 **동시 실행 30개** 제한이 있습니다. 한 반(30명 안팎, 방 6~8개)이 적당하고, 한 수가 1~2초 늦게 반영될 수 있습니다. 오프라인 테이블 모드는 변화가 없으면 확인 간격을 최대 3.5초까지 늘려 서버 부담을 줄입니다. 봇 연습과 한 기기 모드는 서버를 쓰지 않습니다.
- 시트에 닉네임이 남으니 실명 대신 별명을 쓰도록 안내해 주세요.

## 로컬에서 실행하기

```powershell
node tools/dev-server.mjs
```

http://localhost:5173/?api=/api 를 엽니다. `?api=/api`를 붙이면 진짜 앱스크립트 대신 같은 서버 코드를 로컬에서 돌립니다(`server/Code.gs`를 다시 빌드하면 자동으로 새로 불러옴). 탭을 여러 개 열어 방장과 친구 역할을 해 볼 수 있습니다.

- 자가 테스트: 각 게임 주소에 `?test=1`을 붙이면 규칙 테스트 결과가 토스트와 콘솔에 나옵니다.
- 모든 테스트 한 번에: `node tools/test-all.mjs` (Code.gs 빌드 → 게임별 규칙 자가 테스트 → `tests/*.test.mjs` 서버 흐름 테스트)

## 새 게임 추가하기 (체크리스트)

1. **게임 폴더**: `games/<id>/` — `games/flip-duel/`을 본보기로 `index.html`(ui-core.css → kit.css → style.css), `style.css`, `js/main.js`(createShell + Lobby), `game.js`, `scene.js`(TableStage), `audio.js`, `tutorial.js`(TutorialRunner)를 만듭니다.
2. **규칙 엔진**: `games/<id>/js/rules.js`에 순수 함수로 작성합니다(DOM 없이, `export`만, 다른 파일 import 없이). 서버와 브라우저가 같이 씁니다. 봇도 여기에. `runSelfTests()`(무작위 수천 판 시뮬레이션 포함)를 넣어 두세요.
3. **서버 모듈**: `server/games/<id>.js`에서 `registerGame('<id>', { title, minPlayers, maxPlayers, bots, reset, start, act, actor, botDelay, botMove, view, playerView })`를 구현합니다.
   - `view()`에는 **그 사람에게 보여도 되는 정보만** 넣으세요. `mySeat`가 -1(테이블 화면)일 때도 안전하게.
   - 오프라인 테이블 모드를 쓰려면 `offline: { deck, deal, zones, name, … }` 구성품만 넣으면 됩니다(`server/offline-table.js` 맨 위 주석 참고). 클라이언트는 `state.mode === 'offline'`일 때 `OfflineTable`에 맡깁니다.
4. **빌드 등록**: `tools/build-gs.mjs`의 `LIBS`(rules.js)와 `MODULES`(서버 모듈)에 한 줄씩 추가하고 `node tools/build-gs.mjs`를 실행합니다.
5. **허브**: `index.html`에 게임 카드를, `hub.js`의 `GAMES`에 id를 추가합니다.
6. **검증**: `tests/<id>.test.mjs`(온라인·오프라인 흐름, 숨김 정보 검사), 로컬 개발 서버에서 여러 탭으로 끝까지, 375px 세로 화면, 기존 게임 한 번씩 → 앱스크립트를 새 버전으로 배포.

## 개발 메모

- **find-skills로 설치한 스킬**: `mobile-touch`(dylantarre/animation-principles, 2.5K 설치) — 터치 반응 100ms 이내, 눌림 피드백, 손가락을 따라오는 조작 원칙을 손패·종 버튼·타일 놓기에 적용.
  - 보드게임 AI(minimax), 실시간 입력, 드래그 앤 드롭도 찾아봤지만 설치 수 150 미만으로 검증이 부족해 설치하지 않았습니다. minimax(알파-베타 가지치기)는 직접 구현했습니다.
- 이미 있던 스킬 활용: threejs-fundamentals / interaction / animation, card-game, game-ui-ux, google-apps-script, frontend-design.
- pstack의 poteto-mode는 사용자가 직접 `/pstack:poteto-mode`로 실행해야 하는 스킬이라 이번 작업은 일반 흐름 + 병렬 작업자(게임별)로 진행했습니다.

## 오리지널 디자인 고지

이 모음의 게임은 모두 **널리 알려진 게임의 규칙(메커니즘)만 참고해 독자적으로 만든 게임**입니다.

- **타일 배틀**: 전통 클라이밍 카드 게임 규칙을 바탕으로 했습니다.
- **심해 보물섬 탐험대**: 숨은 역할 + 카드 뒤집기 장르의 일반적인 규칙을 바탕으로 했습니다.
- **흑백 뒤집기 대전**: 오래된 공공 보드게임인 리버시 규칙을 따릅니다.
- **컬러 러시 / 비밀번호 해독반 / 숫자 블록 정원 / 급식 다섯!**: 각각 색 맞추기 카드, 숫자 타일 추리, 숫자 타일 세트 만들기, 종 치기 반응 게임 장르의 규칙을 참고했습니다.
- **서라벌학교여행**: 주사위 땅따먹기 보드게임 규칙을 참고해 독자적으로 만든 게임입니다.
- 모든 게임의 이름, 로고, 캐릭터, 카드·타일·돌 그림, 색 배치, 문구, 효과음, 배경음은 이 프로젝트에서 새로 만들었습니다. 특정 상업 게임의 이름, 상표, 아트, 문구, 패키지 디자인은 사용하지 않았습니다.
